# 文档区规则

## 适用范围

本文件覆盖 `docs/` 及其子目录，并与仓库根目录 `AGENTS.md` 叠加生效。与教学写法和文档格式有关的局部规则以本文件为准。

## 局部差异

- `study/` 只保存 16 节学习文档，按 `day01` 至 `day16` 的已确认业务映射推进；参考资料物理目录不一致时先核实，在设计或记忆中保留依据，不擅自改章节顺序。
- `memory/learning-progress.md` 是唯一进度源；其他记忆文件记录方法、事实和欠账，不重复维护章节状态。
- `study/images/` 只存教程需要的图片；Mermaid 能表达时优先用 Mermaid，并使用相对路径引用图片。
- `superpowers/` 保存设计和执行计划，不写学习代码。
- 本项目不使用子 agent。编写与验证直接在当前会话完成；临时副本、脚本和输出统一放本项目 `workspace/`。

## 固定教学方式

本项目沿用 `E:/dev/java/group-buy-market/group-buy-market` 的教学方法，以本项目 [第 3 节](study/day03-PDF转Markdown流程.md) 为直接写作样例；长期偏好见 [教学记忆](memory/teaching-preferences.md)。团购工程整体只读，只借鉴讲法，不照搬其 Java 工具链、业务或本项目未授权的行为。

- 开头只用一两句交代上一节留下什么、本节解决什么和资料入口；正文只保留三个一级业务板块：`## 一、业务流程与设计原因`、`## 二、手敲步骤`、`## 三、必做真实验证`。
- 业务块从真实输入和状态变化推导设计，讲清“缺什么 → 直接写会怎样 → 为什么这样拆”。必要的 Python 语法、框架 API 和术语贴着代码短讲，不独立开术语课。
- 使用真实类名、方法名和状态字段画业务、调用或数据流图；每张 Mermaid 图后紧接白话说明起点、箭头、关键分支及数据变化。
- 手敲按依赖顺序交付：先状态或被引用模块，再配置和使用方。每个代码块前说明解决哪个缺口，代码后说明关键写法与如何观察；中文注释说明职责、数据来源和原因，不复述字面代码。
- 新文件给完整可运行内容，完整文件代码块前紧邻 `**文件**：` 加仓库相对路径。已有文件只改本节所需位置，说明定位；给完整文件时明确无需重抄其他已实现内容。配置增量或讲解片段标清用途，不加整文件抽取标记，不拿片段覆盖整个已有文件。
- 用户以 IDE 和实现文件中的学习期 `__main__` 为主要验证入口。验证按“准备什么 → 打开哪里 → 输入或修改哪里 → 点击运行 → 观察什么 → 为什么 → 失败看哪里”交付；终端命令只做必要准备，不能用多条 `python -c`、heredoc 或探针脚本代替业务操作指导。
- 只给本节必做的正常行为验证。模型、文件、接口尽量使用真实数据和服务；无必要不新增测试文件，不要求用户编写替身或执行破坏性实验。AI 需要的边界、回归和破坏性检查只在隔离副本执行。
- 教程不另设目标清单、阶段①②③、缺口列账、测试条数基线、验证填表、参考差异汇总、选做、重复小结或下一节预告。范围内的必要纠错就近解释，资料摸底经过与版本分歧记入设计或记忆。
- 教程只教业务、知识、操作和预期判据；构建实测、临时目录、哈希、Git 状态、验收日期、环境排障流水和交接汇报在对话说明，需要持久化的事实放唯一进度源或验收记忆。
- 未执行的验证写成操作步骤和预期判据，并标记“未验证（未运行）”；不预填测试结果。模型兜底、依赖安装或编译成功不能当成真实识别通过。
- 此写法从第 6 节及后续教程执行；第 1 至第 5 节按历史保留，本次不回改。项目约定优先于技能的通用章节骨架。

## 本区域的验证方式

- 交付前检查：只有上述三块主线、图后有白话、代码就近有解释、IDE 真实入口可操作、失败定位和退出条件明确、没有工作汇报混入教程。
- 检查相对链接、章节边界、类名、方法名、完整文件标记和相对仓库路径；增量片段不能当整文件抽取。
- 完整文件代码块必须在 `workspace/` 的累积隔离副本中抽取和运行；配置增量按文档定位应用到副本，不直接修改学习代码。
- 用户代码验收时重新读取真实实现；教程代码验证不等于用户代码验收。汇报区分通过、失败、跳过、未运行，不编造条数。
- 章节验收通过后才记录验收结论；教程修订只更新必要的教学约定和接手信息，不把学习进度改成“已通过”。
