# ShopDesk AI 演示交互优化

本轮沿用 `e436cf4` 的雾蓝页面。拖入或选择手册只暂存一份文件，点击「开始导入」才提交。使用现有健康检查与导入状态接口，不修改后端，不新增前端依赖。

| 审阅入口 | 核对重点 |
| --- | --- |
| [导入页](../../app/front/import.html#L50) | 大虚线上传区、点选和拖拽、文件名确认、运行中防止重复提交。 |
| [导入状态显示](../../app/front/import.html#L123) | 进度按后端确认完成的节点计数，PDF 7 步，Markdown 6 步。「当前阶段」由未完成的下一节点推断，不表示节点内部进度。暂时读不到状态时保留最后一次进度和计时，并继续轮询。 |
| [首页检查](../../app/front/index.html#L43) | 检查中、Web 服务可访问、失败可重试，仅代表 Web 响应，不代表依赖服务健康。 |
| [图片预览](../../app/front/chat.html#L70) | 当前和历史回答都能点缩略图看原图；关闭按钮和 `Esc` 都可退出。 |

## 自测结果

- **通过：隔离浏览器。** 旧版缺少上传区域，按预期未通过首条断言。改后通过拖拽与文件选择器、选中文件不发请求、确认后只送一次、拒绝非法格式和多文件、PDF 七步、Markdown 六步、任务失败与丢失。模拟状态接口 503 后，计数和计时保持，接口恢复后继续推进。375px 宽度无横向溢出。
- **通过：检查与图预览。** 夹具通过首页检查中、成功及失败重试；通过实时或历史图片的点击放大、按钮关闭、`Esc` 关闭和焦点恢复。另用上一版实验历史回读 RS-12 的四张真实图片，点击其中一张从 124px 显示高度放大到约 383px，URL 一致，按 `Esc` 后保持阅读位置。

- **通过：真实长耗时 PDF。** 浏览器导入迅饶网关样本，在 `1 / 7` 的 PDF 解析阶段持续计时，约 `02:04` 进入图片处理，`05:01` 达到 `7 / 7`。状态接口返回 `completed`，日志确认 24 条切片入库。写入限于 Milvus `verify_doc_c8c0694c_items`、`verify_doc_c8c0694c_chunks` 和 MinIO `verify-doc-c8c0694c`，保留实验数据。Markdown 的 6 步在夹具中验证，本轮未重新做真实 Markdown 入库。

## 用户验收

1. `uv run uvicorn app.main:app` 启动后打开首页。「检查服务」从「检查中」变为「Web 服务可访问」，不再显示原始 JSON。
2. 导入页点击虚线区，或拖入 [迅饶网关与小米产品通讯配置说明](../doc/迅饶网关与小米产品通讯配置说明.pdf)。先确认看到文件名且没有自动上传，再点「开始导入」。请用独立的 Milvus 集合和 MinIO 桶做实际入库。预期阶段和已完成步骤依次更新；单个节点耗时较长时，进度不会虚涨，已用时间继续走。用 Markdown 试跑时没有「PDF 解析」，总共 6 步。
3. 使用已入库的 RS-12 问答，点击答案区的配图，确认能看大图且可以按 `Esc` 或关闭按钮退出；刷新同一标签页后再对历史回答做同样操作。
