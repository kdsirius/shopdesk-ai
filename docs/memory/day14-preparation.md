## 教程验证（2026-11-18）

- **通过**。检查三段结构、相对链接、图后说明、完整 HTML 文件标记，以及两段 Python 增量在现有入口中的定位。按教程应用到 `workspace/verification/day14/tutorial-20261118/project/`，按清华镜像与短缓存运行教程的 `uv add`，锁文件中各包版本未变。用副本的 CPython 3.11.15 编译，并从副本外的工作目录直接运行其 `api/main.py`。实际版本为 FastAPI 0.163.2、Uvicorn 0.54.0、Pydantic 2.14.3。
- **通过**。实际请求 `/`、`/health`、`/docs`、`/openapi.json` 和练习页，均返回 200。浏览器按钮发出的同源 `GET /health` 正常显示 `{"ok":true}`。Swagger 页面提交合法 JSON 为 200，原问题首尾空白被去掉，缺字段、数字类型和纯空白均显示 422。独立 HTTP 请求确认错误定位在 `body.question`，非法路径定位在 `path.run_id`，`steps` 的下限和上限错误都定位在 `query.steps`。
- **通过**。真实 HTTP 流返回 `text/event-stream`，省略 `steps` 得到三条进度，显式指定 `steps=2` 得到两条。每条进度中的编号和序号正确，最后发送 `complete`，随后响应结束。默认三条在请求后约 1.02、2.05 和 3.06 秒收到。浏览器点击后逐条显示进度，`complete` 到达后 `EventSource.readyState` 为 `CLOSED`，按钮恢复可用，之后观察 3.5 秒，访问日志只出现一次该订阅请求。证据在同一实验目录的 `http-stream-timing.json` 和 `uvicorn.log`。
- **失败后复验通过**。Swagger 自动化第一次点击 `Execute` 时因按钮在视口外未点击成功，随后键盘提交已返回 200，但观察脚本使用了错误的表格选择器。定位真实响应表格后复验，200 与三种 422 均观察到。
