## 跨进程小数值对照的首轮失败与受控复验

首轮验收脚本在用户原样入口已经完成并通过自身断言后，对照历史备份时失败：稀疏向量使用了 `rtol=1e-5, atol=1e-6` 的跨进程数值判据。一项权重为约 `0.09855028`，用户备份为约 `0.09856704`，超出该门限。这是验收探针对数值重复性的要求过严，不是 CSR 行错配或用户入口失败；原失败输出保留，不改写成首轮全部成功。

量化全部 21 块发现：所有稀疏特征集合完全相同；Dense 最大绝对差为 `5.476176738739014e-7`，最小余弦相似度为 `0.9999999999908418`；Sparse 最大绝对差为 `1.675635576248169e-5`。

随后保持模型、输入和实现不变，仅把 CPU 线程数从 4 改为 1，复现同样的最大差异，1 线程下前三块 Sparse 与用户备份逐项相等。因此历史备份只用于核对字段、特征集合和量化差异，不把固定小数位当作业务通过条件。同进程 CSR 对 COO 的精确行对应检查仍保持严格，没有放宽或替换真实模型输出。

续验完成未覆盖的末批与失败回填检查，退出码为 0，最终正式验收结果为通过。没有为修复这个探针误判修改任何用户学习代码。
