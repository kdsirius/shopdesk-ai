## 输入与施工边界

- 本节唯一输入为 `workspace/day07-real-run/state_vector.json`，不是第 5 节旧 `chunks.json`。
- 真实状态顶层有 `item_name`、`item_name_dense_vector`、`item_name_sparse_vector`，`chunks` 中有 21 个带 `item_name`、`dense_vector` 和 `sparse_vector` 的 Chunk。
- Dense 为 1024 维，已经按第 7 节模型配置做 L2 归一化；Sparse 保留模型原始权重，不能在本节资料中宣称其已经 L2 归一化。
- JSON 对象键会把内存中的整数 Sparse 特征编号序列化为字符串；主体 Sparse 和所有 Chunk Sparse 在入库适配时都必须恢复为整数键。
- 名称 `RS PRO RS-12 数字万用表` 的内部空格必须保留。
- 采用方案 A：主体识别节点增加主体集合保存步骤，独立 `NodeImportMilvus` 保存 Chunk 集合；学习期入口按“主体保存 → Chunk 入库”顺序运行。
- 主体集合默认 `kb_item_names`，保存 `pk`、`file_title`、`item_name`、1024 维 Dense 和 Sparse；Chunk 集合默认 `kb_chunks`，保存自增 `chunk_id`、正文元数据、主体、1024 维 Dense 和 Sparse。
- 两个集合都使用 Dense `AUTOINDEX + COSINE` 和 Sparse `SPARSE_INVERTED_INDEX + IP`；Sparse 索引保留 `DAAT_MAXSCORE`、`normalize=True`、`quantization=none`。索引侧 normalize 不改变第 7 节 Sparse 原始权重的事实。
- 两个集合都按当前文档的 `file_title` 幂等清理。主体当前应为 1 条，Chunk 当前应为 21 条；重复运行不应累积为 2 条和 42 条。
- 本节不接正式主图，不重新识别主体，不重新生成 BGE-M3，不实现检索、Hybrid Search、RRF、Rerank、MongoDB、FastAPI、SSE 或前端，不重建外部服务。

## 版本与资料分歧保留

- 参考主体集合代码使用过 `IVF_FLAT`，Chunk 代码使用过 `AUTOINDEX`；本项目当前服务端为 2.5.5，教程统一采用当前客户端和服务端可验证的 `AUTOINDEX`，不照搬 `nlist=128`。
- 参考代码有动态字段和直接传入完整字典的写法；本教程采用 `enable_dynamic_field=False`，显式映射 Schema 字段，避免把学习状态中的无关字段写入数据库。
- 参考流程的删除和插入不是数据库事务；教程明确记录删除成功、插入失败时旧数据可能已经被清理，不编造回滚能力。
