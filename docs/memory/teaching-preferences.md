# 带练教学偏好

## 已确认偏好

- 教程只围绕三块内容：业务流程/原理、细致手敲模块、真实验证。
- Python 语法和框架 API 贴着真实代码短讲，不单独安排大段抽象概念课。
- Java 基础较扎实，Python 是新手；解释重点放在 Python 写法与 Java 习惯的差异。
- 不写假 PDF、假 Milvus、假模型或为了凑反馈的替身流程。
- 对应真实节点尚未出现时，记录为未验证或欠账；出现真实代码后再执行对应验证。
- 验收优先看真实输入、状态变化、异常信息和验证失败原因。
- 教程中的真实验证写成用户可照做的步骤和预期效果；优先使用真实接口、真实文件和 IDE/`__main__` 运行入口，不把终端命令堆成主要教学验证；没有必要时不新增测试文件。
- 下一次会话开始提示词由 AI 在完成本节代码审阅后单独提供，不写进学习教程。
- 教程只写知识、操作和预期效果；环境坑、猜测和本次汇报信息直接在对话中说明，不塞进教程。
- 教程固定采用“业务流程与设计原因 → 手敲步骤 → 必做真实验证”三块结构：先从具体业务问题推导设计，再给完整可运行代码，最后用真实接口/真实输入获得正反馈。外部服务章节优先在实现文件中保留学习期 `__main__` 真实入口，后续接入正式流程后再迁移或删除。
- 每节代码验收通过后，AI 要在验收结论后提供本节可直接使用的 Git 提交信息；AI 不执行提交，用户自行提交。
- 用户提交代码后，AI 负责读取提交后的真实状态，完成教程、进度和项目本地记忆的收尾更新；同时核对 README、协作规则中的目录地图、项目概览、验收手册、当前欠账和下一节输入是否过时，更新实际变化并保留历史验收事实。章节状态只在学习进度维护；收尾文档变更也要提供单独的 Git 提交信息。
- 收尾完成后，AI 提供下一节会话开始提示词；提示词只在对话中提供，不写进教程文档。
- 每天资料的事实来源优先顺序是：当天视频目录图片 → 当天课堂笔记和代码 → `1.笔记/` 补充笔记。
- 用户不执行破坏性实验；教程只提供正常行为验证。需要破坏性实验时由 AI 在 `workspace/verification/` 隔离副本中自行完成，不写进教程步骤。

**Why:** 用户希望减少无关铺垫，把学习时间用于项目业务、Python 框架使用和能证明代码有效的验证；破坏性实验由 AI 负责，避免打断用户手敲流程和污染学习代码。

**How to apply:** 每节先核对“本节真实代码是什么、能验证什么”，再写施工图纸；删除独立的抽象目标、模拟流程、无意义测试代码、破坏性实验步骤、会话提示词和猜测性记录，把必要术语压缩到代码旁边。
