# Python/uv 教学验收手册

> 教程中的代码必须能被抽取并在隔离副本中运行；没有跑过的命令不能写成通过。

## 验收位置

所有实验文件、复制工程、临时脚本、日志和测试输出统一放在 `workspace/`。`reference/` 和用户真实学习代码都不作为破坏性实验目标。

## 文档代码检查

1. 读取教程中的 `**文件**：` 标记。
2. 确认标记后紧邻代码块，路径相对仓库根目录。
3. 确认目标路径不在 `reference/`，不把讲解片段误当成落盘代码。
4. 将代码块写入 `workspace/verification/<章节>/` 的临时副本。
5. 对本章涉及的文件做语法检查和行为探针。

具体抽取脚本可以按章节需要临时写入 `workspace/scripts/`，不把实验脚本混入学习代码。

## Python/uv 运行

根据当前章节真实工程选择命令：

```bash
uv sync
uv run python -m compileall <本章代码目录>
uv run pytest -q
```

需要安装依赖时使用 uv，并使用项目配置的清华 PyPI 镜像；没有实际运行的命令必须标记为“未验证”。若当前章节只有最小脚本而没有 `pyproject.toml` 或测试目录，记录“测试未运行”，使用 Python 探针作为行为验证。

## 破坏性实验

1. 选一个本章明确由测试或探针守护的关键条件。
2. 先读取并记录原文件内容或哈希。
3. 只改一处，例如反转文件类型路由条件、删除状态字段更新或改变节点顺序。
4. 先确认改动已经写入，再运行对应测试或探针。
5. 记录真实错误和失败原因；不能只记录红绿结果。
6. 恢复原内容，用 `git diff --no-index`、哈希或精确文本对比确认恢复。

如果故意改坏后测试仍通过，先排除破坏没有生效；确认破坏生效后仍通过，记录为测试缺口并补充验收意见。

## 状态记录

每次验收都记录：

- 命令和运行位置
- 实际输出
- 测试条数、失败数、错误数、跳过数
- 外部服务是否已启动
- 结果属于 `通过`、`失败`、`跳过` 还是 `未运行`
- 破坏性实验改了什么、哪条断言失败、如何恢复

掉电语义、操作系统调度和真实网络分区等无法在进程内复现的行为，写入进度的“欠账”，不编造测试。

## 用户代码验收

- 读取用户真实文件，不以教程代码代替。
- 复制到 `workspace/verification/<递增编号>/` 后再运行。
- 全量测试条数与上一节基线对比；新增、减少和未运行都要解释。
- 检查测试是否断言过程、请求内容和事件顺序，而不是只断言数量。
- 批改意见分为“必须改 / 建议改 / 可选”。
- 只有通过后才更新 `learning-progress.md`，再生成下一节开始提示词。
