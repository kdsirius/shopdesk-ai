# Python/uv 教学验收手册

> 本文件补充 AI 内部验收操作；教学写法以 [文档区规则](../AGENTS.md) 和 [教学偏好](teaching-preferences.md) 为准。教程完整文件代码在隔离副本中抽取运行，增量按定位应用；没有跑过的命令不能写成通过。

## 验收位置

所有实验文件、复制工程、临时脚本、日志和测试输出统一放在 `workspace/`。`reference/` 和用户真实学习代码都不作为破坏性实验目标。

## 文档代码检查

1. 读取教程中的 `**文件**：` 标记。
2. 确认标记后紧邻代码块，路径相对仓库根目录。
3. 确认目标路径不在 `reference/`，不把讲解片段误当成落盘代码。
4. 将代码块写入 `workspace/verification/<章节>/` 的临时副本。
5. 对本章涉及的文件做语法检查和行为探针。

具体抽取脚本可以按章节需要临时写入 `workspace/scripts/`，不把实验脚本混入学习代码。

## Python/uv 运行

先复制真实源码、依赖清单与锁文件，检查当前解释器和必要的本地模型。只复制本节需要的配置，不把无关服务密钥带进副本。已验收的源码与提交后文件字节一致时，文档收尾只做一致性检查，不无故重复请求外部服务或模型。

下面是操作模板（未验证／未运行），应在已建立的 workspace 隔离工程目录执行；实际解释器与命令以本轮环境检查为准：

```bash
uv sync --locked --python 3.11 --default-index https://pypi.tuna.tsinghua.edu.cn/simple
uv run --locked python -m compileall -q src/shopkeeper_brain
```

当前项目没有 pytest 套件，不默认执行 `pytest`，也不为验收临时给项目新增测试框架。编译和导入只证明准备阶段，仍须用真实节点、真实输入与模型或服务检查行为；无法运行的业务项分别记为跳过或未运行。测试条数仅在实际测试框架确实运行时取输出，行为探针按检查项记录，不换算为测试条数。

## 破坏性实验（仅 AI 内部验收）

破坏性实验不写入学习教程，也不要求用户执行。用户只按教程中的正常行为验证步骤操作。

如果 AI 认为某章需要额外确认测试守护能力，只能在 `workspace/verification/` 的隔离副本中自行完成：

1. 选一个本章明确由探针守护的关键条件。
2. 先读取并记录隔离副本原文件内容或哈希。
3. 只改一处，例如反转文件类型路由条件、删除状态字段更新或改变节点顺序。
4. 先确认改动已经写入，再运行对应探针。
5. 记录真实错误和失败原因；不能只记录红绿结果。
6. 恢复原内容并核对差异，确保不影响用户真实代码。

若不需要破坏性实验，直接跳过，不在教程中为了凑流程而添加。

## 状态记录

每次验收都记录：

- 命令和运行位置
- 实际输出
- 测试条数、失败数、错误数、跳过数
- 外部服务是否已启动
- 结果属于 `通过`、`失败`、`跳过` 还是 `未运行`
- 破坏性实验改了什么、哪条断言失败、如何恢复

掉电语义、操作系统调度和真实网络分区等无法在进程内复现的行为，写入进度的“欠账”，不编造测试。

## 用户代码验收

- 读取用户真实文件，不以教程代码代替。
- 复制到 `workspace/verification/<递增编号>/` 后再运行。
- 有实际自动化测试时记录框架输出；当前项目记为“无自动化测试”，分别报告正常行为、边界和隔离破坏检查的结果。
- 检查输入、状态变化、请求内容与顺序，不只断言结果数量；浮点输出按业务契约判断，不强求跨进程小数位完全一致，数据行映射仍须精确对应。
- 批改意见分为“必须改 / 建议改 / 可选”，不代写用户学习代码；非阻塞建议必须区分“已修改”与“仍保留”。
- 验收结论满足后更新唯一进度源并给用户提交信息。用户提交后只读核对源码、提交与工作区，维护 README、项目概览、进度、验收记录和欠账，再在对话中提供下一节提示词。
- 历史验收保留原始失败及当时环境；后续结清或映射修正写清时间和依据，当前入口不得继续把它们描述成持续故障。
