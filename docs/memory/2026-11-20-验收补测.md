# ShopDesk AI 验收补测

基线为 `00a7fae`，工作树起点为 `db93f1c`。使用 CPython 3.12.13、Ego Browser 和相同源码的隔离副本。原服务的健康检查返回 `{"ok":true}`。补测写入独立的 Milvus 集合、MongoDB 库和 MinIO 桶，保留验收数据以供复核。没有修改应用源码。

## PDF Web 导入

- **首轮失败**。浏览器上传真实 RS-12 PDF，MinerU 返回 ZIP，但解压图片时出现 `FileNotFoundError`。失败路径长 261 字符，Windows 的 `LongPathsEnabled` 为 `0`。首轮隔离服务到达预设运行时限后停止。
- **短路径复验通过**。以字节核对一致的 54 个源码与页面文件启动隔离副本，浏览器看到 7 个导入节点完成。Milvus 实际写入 1 条商品记录、21 个不重复主键的 Chunk，切片正文与导入备份逐条对应。
- **新入库数据问答通过**。浏览器看到 7 个查询进度节点及 154 个不同长度的正文更新状态。首次断言误把红表笔插孔写为 `V/Ω`，直接对照 PDF 转出的原文后确认回答的 `V AC`、黑笔 `COM`、红笔 `V` 均正确。4 张配图成功加载；刷新后两条历史消息、答案和图片一致，MongoDB 记录也已核对。
- **新发现：视觉摘要污染图注**。13 条图注带有结构化消息的字符串表示，如 `![[{'type': 'text', …`。当前答案图片提取仍匹配了 13 条标签，实际问答也成功回显配图。原因定位到[视觉摘要提取](../../app/processor/import_processor/nodes/node_md_img.py#L200)将 `response.content` 直接转字符串。可考虑先用 `response.text` 提取正文，再沿用现有清洗；仅当仍无法生成合法图注时，再讨论校验和回退。未改源码。

复验数据保留在 `verify_doc_3cf7a60b_items`、`verify_doc_3cf7a60b_chunks`、MongoDB `verify_doc_3cf7a60b` 和对象桶 `verify-doc-3cf7a60b`。Windows 长路径问题可先用较短目录规避；如需从应用层解决，可另行讨论缩短临时输出路径。真实浏览器截图见 [README](../../README.md#体验一次商品问答)。
